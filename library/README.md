# Dagger TypeScript library (vendored)

The runtime half of the TypeScript SDK: the client bindings modules talk to the
engine through, and the decorators they are written with. Vendored from
[dagger/dagger][upstream]'s `sdk/typescript` — see [VENDOR.md](./VENDOR.md) for
the exact source, the local deltas, and how to re-import.

This is not a published package and not the thing you install. `npm install
@dagger.io/dagger` gets you upstream's release; what a module generated by this
SDK imports is `bundle/core.js`, built from these sources and committed.

[upstream]: https://github.com/dagger/dagger/tree/main/sdk/typescript

## Layout

| Path | |
|---|---|
| `src/` | The library sources, as vendored. |
| `src/api/client.gen.ts` | Generated, not vendored — rendered from the engine's schema. |
| `bundle/` | Built from `src/` and committed, because module generation reads it and building it there would put a bun toolchain in every `dagger generate`. |

## Working on it

Everything is driven from the repo root; there is no npm workflow here.
`.dagger/modules/packager` owns the build, and its functions are `@generate`
ones — so the engine surfaces them as checks that fail when the committed output
is stale. Editing `src/` without rebuilding the bundle is caught rather than
silently shipped.

```shell
dagger check packager   # what is stale
dagger generate         # rebuild it
```
